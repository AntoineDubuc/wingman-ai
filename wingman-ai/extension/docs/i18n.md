# i18n Maintenance Guide

How to maintain, extend, and ship localized strings in the Wingman extension.

## 1. Architecture overview

Wingman uses [i18next](https://www.i18next.com/) (chosen over `chrome.i18n` per ADR-002) with these constraints:

| Decision | Value | NFR |
|---|---|---|
| Bundle format | One `translation.json` per locale under `src/locales/{locale}/` | NFR-MAINT-01 |
| Loading strategy | Static ES-module imports → all 5 bundles in-memory at SW/page boot | NFR-P02 |
| Locale source of truth | `chrome.storage.sync.language_preference` → fall back to `chrome.storage.local` → fall back to `chrome.i18n.getUILanguage()` (browser detect) | FR-002, FR-003 |
| Fallback chain | Active locale → English → key string (i18next `returnNull: false`) | NFR-R01 |
| Interpolation | i18next default with `{{var}}` (`escapeValue: true` for XSS) | NFR-SEC04 |
| Plural forms | i18next standard with CLDR rules per locale | FR-022 |

Supported locales: **en, fr, es, ro, ru** (5).
Display names: English, Français, Español, Română, Русский.

## 2. Bundle structure

`src/locales/{locale}/translation.json`:

```json
{
  "_meta": {
    "generator": "claude-direct",
    "generated_at": "2026-05-05",
    "revision": "plan-3-r2",
    "reviewer_status": "pending-native-review"
  },
  "popup": {
    "start_session": "Start Session"
  },
  "options": {
    "setup": {
      "language_picker_label": "Language",
      "language_locked_tooltip": "Language locked during active session"
    }
  }
}
```

### `_meta` provenance fields

| Field | Values | Purpose |
|---|---|---|
| `generator` | `claude-direct`, `human`, `mt-cloud-translation`, etc. | Track who/what authored the bundle |
| `generated_at` | ISO date | When the bundle was last touched |
| `revision` | freeform string | Maps to a plan or PR for traceability |
| `reviewer_status` | `pending-native-review`, `native-reviewed`, `canonical-english-source` | Release gate (NFR-Q02) |

The English bundle has `reviewer_status: 'canonical-english-source'`. Non-English bundles must reach `reviewer_status: 'native-reviewed'` (with a paired `docs/i18n-reviews/{locale}-{revision}.md` artifact) before user-facing rollout. See `i18n-review-process.md`.

## 3. Adding a new locale

(Future work; not in v1 scope.)

1. Add to `SUPPORTED_LOCALES` in `src/shared/i18n-types.ts`.
2. Add to `LOCALE_DISPLAY_NAMES` in same file.
3. Create `src/locales/{newlocale}/translation.json` matching English's logical key set (use `scripts/check-i18n-keys.ts` to verify).
4. Verify CLDR plural rules for the new locale; adjust plural-form keys (`_one`/`_few`/`_other`/etc.) accordingly.
5. Run `npm run build` — `BUILD-01` (key exhaustiveness) and `BUILD-03` (Unicode sanitization) must pass.
6. Engage native reviewer per `i18n-review-process.md` before flipping `reviewer_status` to `native-reviewed`.

## 4. Fallback chain (NFR-R01)

```
i18n.t(key)
  → if key exists in active locale → return that string
  → else if key exists in English → return English string  (fallbackLng: 'en')
  → else → return key string itself  (returnNull: false; logs structured warning)
```

Implementation: `src/shared/i18n-init.ts`. The English bundle is statically imported at module load — no async path can leave English unavailable.

## 5. CI gates

| Gate | Script | What it enforces |
|---|---|---|
| BUILD-01 (key exhaustiveness) | `scripts/check-i18n-keys.ts` (run via `npm run build`) | All 5 bundles share the same logical key set; per-bundle ≤ 50KB; total ≤ 250KB |
| BUILD-03 (Unicode sanitization) | `scripts/sanitize-locale-files.ts` (also runs as pre-commit hook via husky) | No homoglyphs, no zero-width, no C0/C1 control chars, NFC normalized |

The plural-form-aware key comparison in BUILD-01 strips i18next plural suffixes (`_one`/`_few`/`_other`/etc.) before comparing logical keys, so locale-specific plural forms (ro/ru 3-form, en/fr/es 2-form) don't register as EXTRA mismatches.

## 6. Adding a new key

1. Add to `src/locales/en/translation.json` first (English is the canonical source).
2. Translate into the other 4 bundles (fr, es, ro, ru). Match the namespace path exactly.
3. For plural forms, use i18next standard suffixes (e.g., `key_one`, `key_other`). Add `_few` for ro/ru where CLDR requires.
4. For interpolation, use `{{var}}` in the value. Default escaping: `escapeValue: true` (HTML-safe). For pre-trusted values (e.g., `{{- locale}}` for displaying user-locale-name), use the unescaped form `{{- var}}`.
5. Run `npm run build` to verify all gates pass.
6. Update `_meta.revision` and `_meta.reviewer_status: 'pending-native-review'` for each non-en bundle.

## 8. Common patterns

### Reading a string in production code

```ts
import { createI18nInstance } from '@shared/i18n-init';
import { languagePreferenceService } from '../services/language-preference';

const locale = await languagePreferenceService.getLanguage();
const i18n = createI18nInstance(locale);
button.textContent = i18n.t('options.setup.language_picker_label');
```

### Listening for cross-context locale changes (Options page only)

```ts
import { handleStorageChange } from './options-locale';

chrome.storage.onChanged.addListener((changes, areaName) => {
  void handleStorageChange(changes, areaName, i18n, () => window.location.reload());
});
```

### Pluralization

```ts
i18n.t('summary.suggestion_count', { count: 5 });
// en → '5 suggestions'  (uses suggestion_count_other)
// fr → '5 suggestions'  (same)
// ro → '5 sugestii'     (uses suggestion_count_few — CLDR ro 3-form)
// ru → '5 предложений'  (uses suggestion_count_other — CLDR ru 3-form)
```

## 9. Operational notes

- **Picker re-renders trigger a full page reload** in the Options page (Plan 2 hand-off). Plan 5 will replace this with a granular section-by-section rerender once all sections are localized.
- **Popup is NOT yet localized** (Plan 4 scope). FR-002 narrative for popup-first users is currently broken.
- **Overlay's Cyrillic fallback is currently undefined** (Plan 6 scope). Russian users may see fallback fonts on the overlay.
- **Pre-commit sanitization** runs `scripts/sanitize-locale-files.ts` on every commit. Bypass only with explicit user consent via `--no-verify` (discouraged; sanitizer catches Unicode footguns).
